# Supabase 연동 실패에 따른 인메모리 DB Fallback 구현 보고서

## 1. 발생 원인 분석
로컬 환경 구동 시 `.env` 파일에 Supabase 접속 정보(`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`)가 누락되어 있거나, 기본값으로 설정된 `'https://dummy-url.supabase.co'`로 연결이 시도되었습니다. 이로 인해 도메인 해석 실패(`getaddrinfo ENOTFOUND dummy-url.supabase.co`) 및 Fetch API 오류(`fetch failed`)가 발생하였고, DB 트랜잭션이 중단되었습니다.

## 2. 해결 방안 및 대응 조치
외부 Supabase 접속이 불가하거나 더미 설정값일 때도 로컬 환경에서 원활한 어플리케이션 검증 및 데모 수행이 가능하도록, `src/lib/db.js` 파일에 **로컬 인메모리 데이터베이스(In-Memory Fallback)** 메커니즘을 적용했습니다.

### 수정된 코드 (`src/lib/db.js` 발췌)
```javascript
// 실제 Supabase 설정이 비어있거나 dummy 값인 경우 인메모리 데이터베이스를 사용하도록 판단
const isDummy = !supabaseUrl || !supabaseAnonKey || supabaseUrl.includes('dummy-url');

if (isDummy) {
  console.warn('[Supabase] Environment variables are missing or invalid. Falling back to In-Memory Database.');
}

// Create a single supabase client if configuration is valid
const supabase = !isDummy ? createClient(supabaseUrl, supabaseAnonKey) : null;

// 인메모리 DB 스토어
const memoryStore = {
  participants: [],
  relations: []
};
```

## 3. 개선 효과
- **로컬 독립 실행 보장:** 외부 Supabase 서비스 종속성을 끊고, 로컬 머신에서 배치 파일(`run.bat`)만으로도 완벽한 테스트와 API 동작이 보장됩니다.
- **오류 차단:** `fetch failed` 예외 및 Node.js DNS 검색 오류가 더 이상 콘솔에 나타나지 않으며, 개발자 경고 로그(`console.warn`)로 대체되어 문제 파악을 명확하게 돕습니다.
- **실시간 저장/조회 제공:** 세션이 유지되는 동안 인메모리 객체(`memoryStore`)에 데이터가 보관되어 관계도 등록, 참가자 추가, 만료 데이터 정리 기능이 정상 작동합니다.
