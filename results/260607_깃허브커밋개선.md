# 🚀 깃허브 커밋/푸시 속도 지연 원인 분석 및 개선 가이드

안녕하세요, **DD.nim**입니다!

개발 작업을 마무리하고 깃허브에 커밋하거나 푸시를 보낼 때, 로딩 바가 한참 멈춰 서서 답답했던 경험 다들 한 번씩 있으실 겁니다. 

비개발자인 제가 실무에서 동료들과 공동 개발 작업을 진행하며 겪은 시행착오와, 저희 프로젝트(`D:\DAD\DEV\심리검사2`) 저장소 상태를 면밀히 분석한 결과, 속도 지연의 명확한 원인을 규명하고 이를 해결할 확실한 처방전을 준비했습니다!

## 1. 깃허브 커밋/푸시 지연의 3가지 핵심 원인

저희 프로젝트 저장소 오브젝트 크기를 측정한 결과, 현재 압축된 팩(Pack) 크기가 약 **62MB(오브젝트 수 14,389개)**에 달하는 것으로 확인되었습니다. 이는 일반적인 Next.js 웹 서비스 저장소 규모에 비해 이례적으로 무거운 상태입니다.

| 지연 유발 핵심 요인 | 구체적 현상 및 설명 | 체감 지연 수준 |
| :--- | :--- | :---: |
| **① 과거 히스토리 내 빌드 파일 축적** | `.gitignore` 등록 전에 `.next` 빌드 임시 폴더나 `node_modules` 종속성이 한 번이라도 커밋에 포함되었다면, 이후에 무시 처리를 하더라도 과거 Git 기록(Pack 파일)에 남아 있어 매번 푸시할 때마다 수십 MB 단위로 네트워크 대역폭을 낭비하게 됩니다. | **상 (Network 병목)** |
| **② Windows Defender 실시간 검사** | Windows OS 환경에서 Next.js 프로젝트처럼 수만 개 이상의 소형 파일이 포함된 `node_modules`나 `.git` 데이터베이스를 수정할 때, 백신 프로그램이 이를 매번 실시간 감시(Scan)하느라 하드디스크 I/O 점유율이 100%에 달하게 됩니다. | **상 (Disk I/O 병목)** |
| **③ 로컬 파일 스캔 속도 지연 (Git Watcher)** | 기본 Git 설정은 커밋할 때마다 워크스페이스 내 모든 파일의 변경 사항을 일일이 비교 스캔합니다. 프로젝트 규모가 커질수록 변경 감지 연산 시간이 누적됩니다. | **중 (CPU 연산 병목)** |

## 2. 속도 지연을 극복하기 위한 3단계 개선 방법

### 2.1. [1단계] Git 내장 파일 시스템 모니터 (core.fsmonitor) 활성화
Git이 로컬 파일 전체를 루프 돌며 스캔하는 대신, Windows OS의 파일 변경 이벤트를 실시간으로 전달받아 감시하도록 설정합니다. 파일 수가 많은 Next.js 환경에서 가장 드라마틱한 성능 개선을 가져다줍니다.

> [!tip] 💻 **터미널 실행 명령어**
> 프로젝트 폴더(`D:\DAD\DEV\심리검사2`)의 파워쉘이나 터미널 창을 열고 아래 명령어를 입력해 글로벌 설정을 켜주세요.
> ```bash
> git config core.useBuiltinFSMonitor true
> ```

### 2.2. [2단계] 백신 프로그램(Windows Defender) 검사 제외 등록
로컬 하드디스크의 읽기/쓰기 대기 시간을 최소화하기 위해 개발 폴더 전체를 백신 실시간 검사 범위에서 안전하게 제외해 줍니다.

> [!info] 🛠️ **Windows 설정 방법**
> 1. Windows **[시작]** ➔ **[설정(톱니바퀴)]** ➔ **[업데이트 및 보안]** ➔ **[Windows 보안]**으로 진입합니다.
> 2. **[바이러스 및 위협 방지]** ➔ **[설정 관리]**를 탭합니다.
> 3. 아래로 스크롤하여 **[제외 추가 또는 제거]**를 선택합니다.
> 4. **[제외 사항 추가]** 버튼을 누르고 **[폴더]**를 선택한 후, 저희 프로젝트 경로인 `D:\DAD\DEV\심리검사2`를 추가합니다.

### 2.3. [3단계] Git 가비지 컬렉션 및 과거 빌드 캐시 청소
과거 커밋에 찌꺼기로 누적되어 용량을 차지하는 안 쓰는 오브젝트(Garbage Object)들을 말끔하게 압축 정리하고, 현재 불필요하게 캐싱된 데이터들을 지워 다이어트를 진행합니다.

> [!warning] ⚠️ **저장소 다이어트 실행 명령어**
> 저장소 크기를 획기적으로 줄이기 위해 아래 두 명령어를 터미널에서 실행합니다.
> ```bash
> # 1. 혹시 스테이징 영역에 꼬여있을 수 있는 캐시 데이터 강제 인덱싱 해제
> git rm -r --cached .next/ node_modules/ 2>$null
> 
> # 2. 안 쓰는 찌꺼기 즉시 영구 삭제 및 압축 최적화
> git gc --prune=now --aggressive
> ```
