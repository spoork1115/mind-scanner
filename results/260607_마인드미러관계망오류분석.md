안녕하세요, **DD.nim**입니다.

사내 동료 간의 케미와 궁합을 확인하는 '마인드미러 관계망' 기능 중, **초대 링크를 복사하여 전달하고 응답을 완료했음에도 관계망에 결과가 반영되지 않는 치명적인 동기화 오류**가 보고되었습니다. 

비개발자인 제가 이 문제의 근본적인 원인을 집요하게 추적하여 발견하였으며, 이를 완벽하게 해결하기 위한 분석 결과를 공유해 드립니다.

---

## 1. 문제 현상 정의

동료가 보낸 초대 링크(`${window.location.origin}/profile?hostId=usr-xxxx`)로 접속하여 테스트를 끝까지 응답하고 제출을 완료하였으나, 다음과 같은 문제가 발생했습니다.
- **호스트 결과 페이지**: 게스트가 추가되지 않고 관계망이 업데이트되지 않은 채 기존 시드(Seed) 데이터만 노출됨.
- **게스트 결과 페이지**: 나를 초대한 호스트의 이름이 노출되어야 할 노드 영역에 호스트의 실명이 아닌 기본값인 '동료' 및 '✨'로만 고정 노출되는 현상 확인.

---

## 2. 근본 원인 분석

코드 탐색 및 네트워크 조회를 통해 확인한 결과, 오류의 원인은 크게 **두 가지 핵심 요인**으로 압축됩니다.

### 2.1. 외부 Cloud DB API (`keyvalue.xyz`) 서비스 중단 및 단절
현재 마인드미러 서비스는 서버리스 환경(Vercel 등)에서 분산 인스턴스 간 데이터를 공유하기 위해 무료 키-값 저장소인 `https://api.keyvalue.xyz` 주소를 사용하고 있습니다. 
그러나 확인 결과, **해당 도메인이 만료되었거나 네임서버 조회가 되지 않는 상태(Domain Resolution Failure - lookup api.keyvalue.xyz: no such host)**로 판명되었습니다.

> [!warning] 원격 데이터 동기화 단절의 나비효과
> 1. API 요청 시작 시 `db.init()` 내의 `loadFromCloud()`가 도메인 단절로 무조건 실패하여 로컬 메모리에는 기본 시드 데이터만 적재됩니다.
> 2. 참가자 등록(`addParticipant`) 및 관계 추가(`addRelation`)를 시도할 때 원격 클라우드 전송(`syncToCloud()`)이 모두 실패합니다.
> 3. 분산된 Next.js 서버리스 환경에서 컨테이너 인스턴스 간 메모리가 동기화되지 않으므로, 게스트가 응답한 세션과 호스트가 페이지를 조회하는 세션의 데이터가 일치하지 않아 관계 데이터가 완전히 유실됩니다.

### 2.2. 관계 데이터 모델 설계 누락 (호스트 정보 미저장)
데이터베이스에 관계 레코드를 저장하는 `db.addRelation` 로직 수행 시, **호스트(Host)의 성명, 역할(직급), 띠, MBTI 등의 핵심 메타데이터가 누락**된 상태로 저장되고 있었습니다.

> [!info] 누락된 필드 매핑 관계
> - `/api/test/submit/route.js`의 `addRelation` 시점에 게스트(Guest)의 정보는 모두 필드로 추가되나, 호스트는 단지 `hostId` 필드 하나만 기록하고 있습니다.
> - 이로 인해 게스트의 결과 화면(`result/page.js`)에서 역방향으로 나를 초대한 호스트의 프로필 정보를 그리고자 할 때, DB에 관련 텍스트 데이터가 없으므로 `rel.hostName || '동료'` 삼항 연산자에 의해 강제로 '동료' 및 '✨'로만 노출되는 레이아웃 버그가 동반되고 있었습니다.

## 3. 해결 방안 수립

동기화 먹통 문제와 UI 표기 오작동을 해결하기 위해 다음과 같은 조치를 취하고자 합니다.

### 3.1. 로컬 파일 시스템 기반의 JSON DB (`db-store.json`) 도입
작동하지 않는 외부 클라우드 KV API를 제거(혹은 안전하게 예외처리 및 미사용화)하고, 로컬 개발 환경 및 지속 테스트 환경에서 데이터가 영속적으로 유지되도록 **`fs` 모듈을 이용한 로컬 JSON 파일 백업 스토어 시스템**을 구축합니다.
- `src/data/db-store.json` 파일 생성 및 데이터 입출력 처리.
- 서버가 재기동되거나 모듈 갱신(HMR)이 일어나도 테스트 데이터가 완벽히 보존되도록 개선.

### 3.2. 관계 데이터 모델 구조 개선 (호스트 프로필 저장 및 렌더링 연동)
관계를 기록할 때 호스트 유저의 데이터 정보(`hostName`, `hostMbti`, `hostZodiac`, `hostRole`)도 레코드 내에 포함하여 저장하도록 `/api/test/submit/route.js`를 수정하고, 이를 `/result/page.js` 화면에서 정상적으로 맵핑하도록 보완하겠습니다.

> [!tip] 기대 효과
> 이번 조치가 완료되면 초대 링크를 통한 응답 결과가 완벽히 로컬 데이터베이스에 누적 및 보존되며, 호스트와 게스트 모두 실시간으로 연결된 인터랙티브한 관계도(Relation Map)를 확인할 수 있게 됩니다.
