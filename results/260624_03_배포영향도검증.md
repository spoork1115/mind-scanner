# Vercel 배포 환경 영향도 검증 보고서

## 1. 검증 목적
로컬 환경의 Supabase 미연동 에러를 해결하기 위해 도입된 인메모리 DB Fallback 기능이 기존 Vercel 프로덕션 배포 및 실서비스 Supabase 데이터베이스와의 통신에 미치는 영향을 평가합니다.

## 2. 검증 결과 (안전함)
수정된 코드는 Vercel 배포 환경에서 **기존 Supabase 데이터베이스와 정상적으로 통신하며 영향도가 전혀 없음**을 확인했습니다.

## 3. 기술적 세부 분석
`src/lib/db.js` 파일에 적용된 환경 변수 감지 로직은 다음과 같이 동작합니다.

```javascript
const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL;
const supabaseAnonKey = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY;

// 1. 실제 Supabase 설정 유무 및 dummy 여부 검증
const isDummy = !supabaseUrl || !supabaseAnonKey || supabaseUrl.includes('dummy-url');
```

- **Vercel 환경 (프로덕션):** Vercel 시스템 설정에 `NEXT_PUBLIC_SUPABASE_URL` 및 `NEXT_PUBLIC_SUPABASE_ANON_KEY`가 올바르게 등록되어 있으므로 `isDummy`는 `false`가 됩니다.
- **클라이언트 초기화:** `isDummy`가 `false`일 때 `supabase` 클라이언트가 온전히 생성됩니다.
- **데이터 흐름:** 모든 API 조회/삽입/만료 처리 함수에서 `if (isDummy)` 조건문을 거치지 않고, 하단의 기존 Supabase 데이터베이스 쿼리를 정상적으로 타게 됩니다.

따라서 배포 시에는 로컬 인메모리 임시 저장소가 작동하지 않으며, 실데이터는 기존과 같이 Supabase 테이블에 직접 영구 저장됩니다.
